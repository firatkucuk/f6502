Using f6502

Everything you need to embed the Commodore 64 in a web page, drive it from TypeScript, or compile C64Script programs — all without a backend or native dependencies.

Install & build

Install from npm — the package ships pre-built ESM and an IIFE bundle:

shell 
npm install f6502

Then import the parts you need:

TypeScript / ESM 
// High-level browser player
import { start, Player } from 'f6502';

// Bare 6502 CPU core
import { MOS6502, type Bus } from 'f6502';

// Full C64 machine
import { C64 } from 'f6502';

// C64Script compiler
import { compile } from 'f6502/c64script';

Or load the pre-built IIFE bundle from a CDN — no build step required:

CDN (unpkg / jsdelivr) 
<!-- unpkg -->
<script src="https://unpkg.com/f6502/dist/f6502.min.js"></script>

<!-- jsdelivr -->
<script src="https://cdn.jsdelivr.net/npm/f6502/dist/f6502.min.js"></script>

<!-- the bundle exposes a global F6502 object -->
<script>
  F6502.start({ canvas: '#screen', roms: { /* ... */ } });
</script>

To build from source:

shell 
git clone https://github.com/firatkucuk/f6502
cd f6502
npm install
npm run build     # → dist/index.js (ESM) + dist/f6502.min.js (IIFE)

Browser usage

The quickest path to a running C64 in the browser is F6502.start(). It creates the machine, wires up canvas rendering, keyboard input, and optionally Web Audio, then returns a Player you can control.

index.html — minimal 
<canvas id="screen"></canvas>
<script src="f6502.min.js"></script>
<script>
  F6502.start({
    canvas: '#screen',
    roms: {
      kernal:  'roms/kernal.rom',
      basic:   'roms/basic.rom',
      chargen: 'roms/chargen.rom',
    },
  });
</script>
index.html — all options 
const player = await F6502.start({
  /* required */
  canvas: '#screen',               // CSS selector or HTMLCanvasElement
  roms: {
    kernal:  'roms/kernal.rom',    // URL, Uint8Array or ArrayBuffer
    basic:   'roms/basic.rom',
    chargen: 'roms/chargen.rom',
  },

  /* optional */
  program: 'games/invaders.prg',   // auto-load after READY. prompt
  scale: 2,                        // integer | 'fit' (CSS scales canvas)
  audio: true,                      // true | { sampleRate?, model? }
  keyboardTarget: 'document',      // 'canvas' (default) | 'document'
});

Option details

scale: number | 'fit'

A plain number (e.g. 2) sets the canvas CSS size to 384 × scale by 272 × scale pixels. 'fit' leaves sizing to your CSS — the canvas renders at its natural 384 × 272 resolution, perfectly pixelated.

audio: boolean | { sampleRate?: number; model?: '6581' | '8580' }

Set true to enable SID audio through an AudioWorklet. Audio starts after the first user gesture (browser autoplay policy). model selects between the original 6581 (warmer, with the classic filter) and the revised 8580. Falls back to silence with a console notice if the browser lacks AudioWorklet.

keyboardTarget: 'canvas' | 'document'

'canvas' (default) — keyboard events only reach the emulator when the canvas has focus. Click the canvas to focus it. 'document' — keyboard events are captured globally, useful when you don't want the canvas to be focused.

Player API

start() returns a Player instance that lets you control the running machine:

player.running: boolean

Read-only. true while the emulation loop is active.

player.pause(): void

Stops the emulation loop and mutes audio. Held keys are released.

player.resume(): void

Restarts the emulation loop after a pause().

player.reset(): void

Triggers a C64 hardware reset (equivalent to pressing the reset button).

player.load(source: Source, options?): Promise<void>

Loads a PRG file. Waits (up to 12 emulated seconds) for the BASIC READY. prompt, then loads and runs the program. Source accepts a URL string, URL object, File, Blob, Uint8Array, or ArrayBuffer.

player.type(text: string): void

Injects a string into the keyboard queue, as if the user typed it. Great for automating BASIC commands — e.g. player.type('LIST\n').

player.destroy(): void

Stops the emulation loop, removes event listeners, and closes the audio context. Call this when removing the emulator from the page to prevent memory leaks.

Loading ROMs

ROMs are never bundled. C64 firmware is copyrighted by Commodore / Cloanto and cannot be redistributed. You must supply your own, or use the free OpenROMs project.

OpenROMs is an Apache-2.0 licensed clean-room reimplementation of the C64 ROMs maintained by the MEGA65 team. They are fully compatible with f6502.

Downloading OpenROMs for local development

shell 
npm run fetch-test-data
# Downloads to .testdata/openroms/bin/
#   kernal_generic.rom
#   basic_generic.rom
#   chargen_openroms.rom

Fetching ROMs at runtime in the browser

TypeScript 
// Pass URL strings — start() fetches them automatically
await start({
  canvas: '#screen',
  roms: {
    kernal:  '/roms/kernal.rom',  // cross-origin needs CORS headers
    basic:   '/roms/basic.rom',
    chargen: '/roms/chargen.rom',
  },
});

// Or fetch yourself and pass ArrayBuffers
const [kernal, basic, chargen] = await Promise.all([
  fetch('/roms/kernal.rom').then(r => r.arrayBuffer()),
  fetch('/roms/basic.rom').then(r => r.arrayBuffer()),
  fetch('/roms/chargen.rom').then(r => r.arrayBuffer()),
]);
await start({ canvas: '#screen', roms: { kernal, basic, chargen } });

The Source type accepted everywhere ROMs or programs are loaded:

TypeScript 
type Source =
  | string        // URL string — fetched automatically
  | URL           // URL object
  | Uint8Array    // raw bytes
  | ArrayBuffer   // raw buffer
  | Blob          // browser Blob
  | File;         // <input type="file"> result

Bare 6502 CPU

You can use MOS6502 on its own — no C64 machine, just the raw processor wired to any memory you provide. Every bus.read / bus.write call is exactly one CPU cycle.

TypeScript 
import { MOS6502, type Bus } from 'f6502';

const mem = new Uint8Array(0x10000);

const bus: Bus = {
  read:  (addr) => mem[addr]!,
  write: (addr, val) => { mem[addr] = val; },
};

// Place reset vector at $FFFC/$FFFD → $0200
mem[0xfffc] = 0x00;
mem[0xfffd] = 0x02;

// LDA #$42  →  STA $0300
mem.set([0xa9, 0x42, 0x8d, 0x00, 0x03], 0x0200);

const cpu = new MOS6502(bus);
cpu.reset();   // reads reset vector, sets PC = $0200
cpu.step();    // executes LDA #$42 (2 cycles)
cpu.step();    // executes STA $0300 (4 cycles)

console.log(mem[0x0300]!.toString(16));  // → "42"

You can also hook into every cycle via the onCycle callback — useful for driving other chips in lockstep:

TypeScript — onCycle hook 
const cpu = new MOS6502(bus, {
  onCycle: () => {
    vic.tick();
    sid.tick();
    cia.tick();
  },
});

Full C64 machine

C64 assembles the entire machine — CPU, VIC-II, SID, CIAs, memory map — and provides a frame-level API.

TypeScript 
import { C64 } from 'f6502';
import { readFileSync } from 'node:fs';

const kernal  = readFileSync('.testdata/openroms/bin/kernal_generic.rom');
const basic   = readFileSync('.testdata/openroms/bin/basic_generic.rom');
const chargen = readFileSync('.testdata/openroms/bin/chargen_openroms.rom');

const c64 = new C64(
  { kernal, basic, chargen },
  { sid: { model: '6581' } },   // optional SID config
);

// Run 50 PAL frames (50 × 19,656 cycles ≈ 1 second of C64 time)
for (let i = 0; i < 50; i++) c64.runFrame();

// Render the latest frame
// c64.frame.pixels is a Uint32Array, 384 × 272 RGBA little-endian values
ctx.putImageData(
  new ImageData(new Uint8ClampedArray(c64.frame.pixels.buffer), 384, 272),
  0, 0
);

C64 machine API

c64.runFrame(): void

Advances the machine by exactly one PAL frame (19,656 CPU cycles).

c64.frame.pixels: Uint32Array

The rendered frame: 384 × 272 RGBA pixels, updated after each runFrame().

c64.pokeRam(addr: number, value: number): void

Write directly to RAM, bypassing the memory map and bank switching.

c64.peekRam(addr: number): number

Read directly from RAM.

c64.reset(): void

Hardware reset — equivalent to pressing the C64's reset button.

c64.keyDown(key: C64Key): void

Press a key on the C64 keyboard matrix.

c64.keyUp(key: C64Key): void

Release a key on the C64 keyboard matrix.

c64.type(text: string): void

Queue a string of characters to be "typed" into the keyboard buffer.

C64Script integration

The C64Script compiler is bundled with f6502. It turns TypeScript-flavoured source into a raw PRG binary you can load straight into the emulator.

TypeScript 
import { compile } from 'f6502/c64script';

const prg: Uint8Array = compile(`
  program(0x0810) {
    var color: byte @zp = 0;
    loop {
      c64.border = color;
      color = color + 1;
      if (color == 16) { color = 0; }
    }
  }
`);

// Load into a running Player
await player.load(prg);

// Or save to disk in Node
import { writeFileSync } from 'node:fs';
writeFileSync('rainbow.prg', prg);
compile() is synchronous — it throws a typed error (LexError, ParseError, TypeError, or CodeGenError) on failure, all importable from f6502/c64script.

See the C64Script language reference for the full syntax, built-in hardware registers, and more examples.
