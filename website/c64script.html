TypeScript for the 6502

C64Script

Write Commodore 64 programs in a language that feels familiar. C64Script compiles directly to 6502 machine code — no assembly, no linker scripts, no makefile. Just TypeScript-like syntax that becomes bytes your C64 can run.

▶ Open the Playground Try in the Demo View compiler source

Language features

Everything you need, nothing you don't

C64Script targets the 6502's constraints directly. Every feature maps cleanly to machine instructions — there is no runtime, no garbage collector, no hidden overhead.

🔤

Familiar TypeScript-like syntax

Variable declarations, typed globals, if/else, loops, functions — the structure you already know, targeting 8-bit hardware from 1982.

⚡

Zero-page annotation @zp

Mark variables @zp to place them in zero page ($00–$FF). The 6502 can address these with a single byte instead of two, making every access faster and smaller. You get 246 bytes of zero-page space ($02–$F7).

🔌

Hardware register access @addr

Pin any variable to a specific memory address. The built-in VIC2.*, SID.*, CIA1.* and CIA2.* fields use this — they are just fields bound to chip registers, not magic.

🎨

Color constants

All 16 C64 colors are built-in constants: COLOR_BLACK, COLOR_WHITE, COLOR_RED, COLOR_CYAN, COLOR_PURPLE, COLOR_GREEN, COLOR_BLUE, COLOR_YELLOW, COLOR_ORANGE, COLOR_BROWN, COLOR_LIGHT_RED, COLOR_DARK_GREY, COLOR_MEDIUM_GREY, COLOR_LIGHT_GREEN, COLOR_LIGHT_BLUE, COLOR_LIGHT_GREY. They fold to immediate values at compile time — no runtime cost.

🔁

Loops and conditionals

while, for, loop (infinite), break, continue. if / else if / else chains; a branch can skip a block of any size.

🧩

Functions

Define reusable fn blocks with u8 parameters and a return type. Calls compile to JSR/RTS, or inline the body when marked @inline. Parameters live in fixed zero-page slots, so there is no recursion.

Examples

See it in action

rainbow-border.c64s 
// Cycle the border through all 16 C64 colours
let @zp color: u8 = 0;
let @zp ticks: u8 = 0;

program @ 0x0810 {
  loop {
    // wait for one video frame
    while (VIC2.rasterLine != 200) {}
    while (VIC2.rasterLine == 200) {}

    ticks = ticks + 1;
    if (ticks == 5) {
      ticks = 0;
      color = color + 1;
      if (color == 16) { color = 0; }
      VIC2.borderColor = color;
    }
  }
}

Use a function to keep the main loop clean. Parameters are u8 values bound to fixed zero-page slots, so a function cannot call itself:

function.c64s 
// A function without parameters, called from the main loop
let @zp shade: u8 = 0;

fn nextShade(): void {
  shade = shade + 1;
  if (shade == 16) { shade = 0; }
}

program @ 0x0810 {
  loop {
    while (VIC2.rasterLine != 200) {}
    while (VIC2.rasterLine == 200) {}
    nextShade();
    VIC2.bgColor0 = shade;
  }
}
Pro tip — variables live in zero page. Every let is allocated in zero page automatically (246 bytes in total), so reads and writes are 2-byte instructions instead of 3. const values take no memory at all: they fold into the code.

Use color constants directly — they compile to zero-cost immediates:

colors.c64s 
// Colour constants compile to immediates
program @ 0x0810 {
  VIC2.borderColor = COLOR_BLUE;       // → LDA #6 ; STA $D020
  VIC2.bgColor0    = COLOR_LIGHT_BLUE; // → LDA #14; STA $D021

  loop {}  // run forever
}

Language guide

Program structure

A C64Script file is a list of declarations plus exactly one program block.

Top-level itemWhat it is
program @ 0x0810 { … }Required, once. The address (a number, or a constant expression) is where the code is loaded and started. The body runs top to bottom and then starts over; end it with loop {} to hold the final state.
let / constGlobal variables and constants.
fn name(…): type { … }Functions. They can be declared before or after the place they are used.
data @addr(0x0D40) { name: [u8; 63] = [ … ]; }Bytes placed at a fixed address (a number or a constant): sprite shapes, lookup tables. A block that would overlap the code is a compile error.
hardware NAME @ 0xD000 { field: u8 @ 0x20 }A register block like VIC2. Put readonly, writeonly or read_to_clear before a field to restrict access.
structReserved: it parses but cannot be used yet.

Comments are // to the end of the line (there are no block comments). Statements end with ; and blocks use { }.

restarts.c64s 
// No loop {} at the end: the program starts over each time it
// reaches the closing brace, so the border colour keeps changing.
program @ 0x0810 {
  VIC2.borderColor = VIC2.borderColor + 1;
}

Language guide

Variables and constants

Variables live in zero page, constants live only in the code.

DeclarationMeaning
let x: u8 = 5;A variable. It is placed in zero page for you and is 0 when no initial value is given. A global's initial value must be a constant expression.
let @zp x: u8;The same, spelled out.
let @addr(0x0400) cell: u8;A name for a fixed address (a number or a constant declared above): no storage is allocated. This is how hardware registers are declared.
const MAX: u8 = 200;A compile-time constant: no memory, folded into the code, usable in other constants and in initialisers.

Scope

A variable declared inside a function or the program block is visible from its declaration to the end of that function. A name can be declared once per function: it may not shadow a global or a name from an enclosing block, but sibling blocks (two for (let i …) loops) can reuse a name and share one slot. A declaration runs every time control reaches it, so a local without an initial value starts at 0 each time.

Zero page holds 246 bytes ($02–$F7) for all variables, parameters and locals together. u8 arithmetic wraps modulo 256, and a constant above 255 is an error for a u8. Array, pointer and struct declarations are accepted but cannot be used yet (indexing is a compile error; see what is not in the language yet).

variables.c64s 
// Constants fold at compile time; variables live in zero page.
const LIMIT: u8 = 5 * 2;
const STEP: u8 = 3;

let total: u8 = 0;

program @ 0x0810 {
  let n: u8 = 0;            // starts at 0 each time this line runs
  while (n < LIMIT) {
    total += STEP;          // u8: wraps past 255
    n++;
  }
  VIC2.borderColor = total & 15;
  loop {}
}

Naming an address

A u16 constant is an address you can name once and reuse. It works wherever a number does, including the places that need an address: program @ START, data @addr(TABLE), let @addr(CELL) x: u8; and ${TABLE} in assembly. program and data addresses may use a constant declared anywhere in the file; a let @addr(…) needs its constant declared above it.

addresses.c64s 
// Name an address once, use it everywhere.
const TABLE: u16 = 0x0C00;

data @addr(TABLE) {
  shades: [u8; 4] = [COLOR_RED, COLOR_ORANGE, COLOR_YELLOW, COLOR_WHITE];
}

program @ 0x0810 {
  asm {
    ldx #3
  next:
    lda ${TABLE},x         // read the table back
    sta $D020              // counting down, so it ends on the first entry: red
    dex
    bpl next
  }
  loop {}
}

Literals and expressions

Values are 8-bit. Anything wider needs u16 and the rules in the types table.

Operator precedence

TightestasCast: x as u8, x as u16. Narrowing a u16 into a u8 needs as u8 or lo().

Prefix ! is logical NOT (1 for 0, else 0) and parentheses group. The assignment forms are =, +=, -=, &=, |= and ^=; x++ and x-- are statements.

One rule to know. A value is computed in the accumulator, so the left operand of + - & | ^ and of a comparison can be any expression, but the right operand must be a literal, a variable, a constant or a hardware register. (a + b) & 6 works; a + (b + 1) is an error that tells you to assign b + 1 to a variable first.
expressions.c64s 
let a: u8 = 6;
let b: u8 = 3;

program @ 0x0810 {
  let mask: u8 = (a + b) & 0b0111;    // left side may be any expression
  let step: u8 = b + 1;               // right side: a variable or a literal
  VIC2.borderColor = (mask ^ step) | 0x08;
  VIC2.bgColor0 = !mask;              // logical NOT: 1 only when mask is 0
  loop {}
}

Language guide

Control flow

Braces are always required, and a condition is a comparison or any value (non-zero is true).

StatementWhat it does
if (c) { … } else if (c) { … } else { … }Chains of any length. There is no elif and no brace-less form.
while (c) { … }Repeats while the condition holds.
for (let i: u8 = 0; i < n; i++) { … }The first part declares or assigns; the step must be i++ or i--; all three parts are required.
loop { … }Forever, until a break. A program that should stop at a final state ends with loop {}.
break; continue;Leave or restart the innermost loop. Outside a loop they are compile errors.
return; return value;Leave the function (see Functions).

Comparisons are unsigned (200 > 100 is true, 255 < 0 is false). && and || are not in the language yet: nest the if statements, or use a flag variable.

branching.c64s 
let @zp x: u8 = 3;

program @ 0x0810 {
  if (x == 1) {
    VIC2.borderColor = COLOR_RED;
  } else if (x == 3) {
    VIC2.borderColor = COLOR_GREEN;
  } else {
    VIC2.borderColor = COLOR_BLUE;
  }

  // two conditions: nest instead of &&
  if (x > 1) {
    if (x < 5) {
      VIC2.bgColor0 = COLOR_YELLOW;
    }
  }
  loop {}
}
loops.c64s 
program @ 0x0810 {
  let n: u8 = 0;
  while (n < 5) { n++; }

  for (let i: u8 = 0; i < 10; i++) {
    if (i == 3) { continue; }      // skip 3
    if (i == 8) { break; }         // stop at 8
    VIC2.borderColor = i;
  }

  loop {                           // forever, until break
    n++;
    if (n == 200) { break; }
  }
  VIC2.bgColor0 = COLOR_BLUE;
  loop {}
}

Language guide

Functions

Parameters and return values are u8 or bool; a function with no result returns void.

FeatureHow it works
ParametersEach one gets a fixed zero-page slot. The arguments are evaluated left to right and stored there, then the function is called with JSR.
Return valuereturn value; puts it in the accumulator; a call can be used wherever an expression can.
@inlineThe body is copied into each call site: no JSR, so a little faster and larger. An inline function cannot contain return.
OrderA function may be called before it is declared.
No recursionThere is no stack frame, so a function cannot call itself, directly or through another function. For the same reason f(f(1)) is an error: put the inner call in a variable first.
From assemblyjsr ${name} calls a function from an asm block.
functions.c64s 
fn clamp(v: u8, max: u8): u8 {
  if (v > max) { return max; }
  return v;
}

@inline fn border(c: u8): void {
  VIC2.borderColor = c;
}

program @ 0x0810 {
  let level: u8 = clamp(200, 15);   // 15
  border(level);
  loop {}
}

Escape hatch

Inline assembly

asm { … } drops to raw 6502 for loops, indexed stores and anything the language cannot express yet. The official 6502 instructions are supported, one per line, and program variables and constants come in through ${…}.

You writeMeaning
lda #$1B · #0x1B · #27 · #'H'Immediate. $ and 0x are hex; 'H' is a screen code.
lda ${count}A variable's address (zero page when it is there). A const gives its value.
sta ${screen(0, 0)},xAny constant expression: screen(), color(), constants, + n.
lda #lo(${TABLE}) · hi(...)One byte of a constant 16-bit value.
loop: … bne loopLabels end with : and belong to their asm block.
jsr ${redraw}Calls a C64Script function.
lda ($FB),y · asl aIndirect and accumulator forms.
fill.c64s 
// Fill screen RAM with a solid block
program @ 0x0810 {
  asm {
    lda #$A0
    ldx #0
  fill:
    sta ${screen(0, 0)},x
    sta ${screen(0, 0) + 256},x
    sta ${screen(0, 0) + 512},x
    sta ${screen(0, 0) + 744},x
    inx
    bne fill
  }
  loop {}
}
Rules. Official opcodes only (no undocumented ones). An address below $100 uses the zero-page form when the instruction has one. Branches reach -128..+127 bytes and a farther one is a compile error naming the label. The compiler keeps no value in a register across statements, so an asm block can go anywhere; leave the stack balanced and the decimal flag clear. asm clobbers(A, X, Y, flags) is accepted and checked, but not needed. A u8 constant is a value and cannot be stored to; a u16 constant is an address and can.

Type system

Types and annotations

TypeWidthRangeNotes
u8 8-bit 0 – 255 Maps to the 6502 accumulator. All arithmetic is modulo 256, and comparisons are unsigned.
u16 16-bit 0 – 65535 Can be assigned, copied, incremented and read with lo() / hi(). Arithmetic and comparison on it are compile errors for now; use u8, or asm.
bool 8-bit true / false Stored as 1 and 0. Usable directly as a condition, and negated with !.

Annotations

AnnotationEffect
(none) let x: u8 is placed in zero page for you; const X: u8 = 5 is a compile-time constant with no storage. Both accept constant expressions as initialisers.
@zp Place variable in zero page ($00–$FF). Generates shorter, faster opcodes. Max 246 bytes in total ($02–$F7) across all variables.
@addr(0x0D40) Place a data block (data @addr(0x0D40) { … }) at a fixed address. The built-in VIC2, SID, CIA1 and CIA2 hardware fields are bound to chip registers the same way.

Built-in functions

FunctionWhat it does
poke(address, value) Stores a byte. The address must be known at compile time; the value can be any expression.
clrscr() Clears screen RAM to spaces and colour RAM to black.
puts(row, col, "TEXT" [, colour]) Writes text at a screen position, and colours it when a colour is given. Row, column and colour are constants; the text must fit on the line.
screen(row, col) The screen RAM address of a character cell: $0400 + row × 40 + col. Rows are 0–24, columns 0–39; both must be constants.
color(row, col) The colour RAM address of the same cell: $D800 + row × 40 + col.
spritePtr(addr) The value for a sprite pointer (addr / 64). The address must be a constant on a 64-byte boundary inside the first 16 KB; anything else is a compile error.
lo(x), hi(x) The low or high byte of a u16 variable or constant.
position.c64s 
// Row 12, column 15: screen code 8 is the letter H
program @ 0x0810 {
  poke(screen(12, 15), 8);
  poke(color(12, 15), COLOR_WHITE);
  loop {}
}

Text and characters

'H' is a character literal and "HELLO" a string. Both mean C64 screen codes: the byte you store in screen RAM to show a character (A = 1 … Z = 26, space, digits and punctuation keep their ASCII value, @ = 0). Lowercase letters are a compile error, because their screen codes depend on the active character set. A string is only valid as the text of puts(); a character is an ordinary u8 constant.

text.c64s 
// Text and colour in one call, then a single character
program @ 0x0810 {
  clrscr();
  puts(12, 15, "HELLO C64", COLOR_WHITE);
  poke(screen(10, 20), 'H');
  poke(color(10, 20), COLOR_YELLOW);
  loop {}
}

Memory address constants

A few well-known addresses are pre-defined as u16 constants, so poke(0x07F8, 53) can read as what it means. Hardware registers are not here: they are fields of VIC2, SID, CIA1 and CIA2. Like colours, they cannot be redefined.

// Name the sprite's address once; spritePtr() does the division by 64.
const SHAPE: u16 = 0x0D40;

data @addr(SHAPE) {
  dot: [u8; 3] = [0x18, 0x3C, 0x18];
}

program @ 0x0810 {
  poke(SPRITE_PTRS, spritePtr(SHAPE));
  VIC2.spriteEnable = 1;
  VIC2.sprite0x = 100;
  VIC2.sprite0y = 100;

Internals

Compiler pipeline

The compiler is a clean six-stage pipeline, each stage transforming one data structure into the next. The whole thing is <1,500 lines of TypeScript.

📖 Lexer source → tokens
🌳 Parser tokens → AST
🔍 Checker validates & folds
⚙️ CodeGen emits opcodes
🔗 Linker resolves fixups
💾 PRG Writer → Uint8Array

Stage 1 — Lexer

Scans the source character-by-character and produces a flat list of typed tokens: keywords, identifiers, integer literals, operators, and punctuation. Throws LexError on unexpected characters.

Stage 2 — Parser

Consumes the token stream and builds an AST (Abstract Syntax Tree). The grammar is hand-written recursive descent — no parser generator. Throws ParseError on unexpected tokens or structural errors.

Stage 3 — Type Checker

Two-pass analysis. Pass 1 collects all function signatures and variable declarations. Pass 2 validates types, resolves @zp / @addr annotations, and folds constant variables — variables declared without an annotation whose initialiser is a literal get a constValue field, so the code generator emits an immediate mode opcode rather than a memory access. All 16 color constants are folded this way. Throws TypeError.

Stage 4 — Code Generator

Walks the checked AST and emits 6502 opcodes into a CodeBuffer. Labels and forward-jump targets are recorded as fixups — placeholder bytes that the linker patches. Zero-page allocation is tracked to avoid collisions. Throws CodeGenError for things like calling an undefined function.

Stage 5 — Linker

Iterates through all fixups and patches the placeholder bytes with the resolved addresses. Branch fixups use signed 8-bit offsets (branch8); absolute jumps use 16-bit little-endian values (abs16). Zero-page fixups use single-byte addresses.

Stage 6 — PRG Writer

Prepends the 2-byte little-endian load address (e.g. $08 $10 for address $1008) to the byte buffer. The result is a valid Commodore PRG file that F6502.player.load() or any real C64 can load directly.

API

Using the compiler from JavaScript

compile-and-run.ts 
import { compile, C64ScriptError } from 'f6502';

const source = `
  program @ 0x0810 {
    loop { VIC2.borderColor = VIC2.borderColor + 1; }
  }
`;

try {
  const prg: Uint8Array = compile(source);
  // prg is a valid .prg file (load address + machine code)
  await player.load(prg);
} catch (err) {
  if (err instanceof C64ScriptError) {
    // every compiler error carries the source position
    console.error(`${err.name} at ${err.line}:${err.col}:`, err.message);
  }
}

Error types

All of them extend C64ScriptError, which carries line and col. In a plain <script> tag the compiler is F6502.compile.

Roadmap

Current limitations

C64Script is young. Here's what's not there yet — and why.

NO MUL / DIV

No multiplication or division

Missing native 6502 instruction

The 6502 has no multiply or divide opcode. Workarounds exist (repeated addition, shift-and-add), but C64Script doesn't generate them yet. Use bit-shifts & / | for power-of-two multiples.

NO ARRAYS

No arrays or pointers

Design in progress

Indexed addressing (e.g. LDA $C000,X) is powerful on 6502, but mapping it to a safe language construct is non-trivial. Array indexing parses but is a compile error for now. Use asm {} with ,x / ,y indexed addressing in the meantime.

LIMITED STRINGS

Strings only inside puts()

Screen codes, uppercase only

String literals are screen codes and are accepted only as the text of puts(); there is no string variable, no PETSCII output and no lowercase yet. A string cannot be passed to a function or stored.

PARTIAL

u16 type is partial

16-bit operations need more work

u16 variables can be assigned, copied, incremented, added to and subtracted from (+, -, +=, -=, mixing in u8 values) and read with lo() / hi(). Comparison on them is a compile error until 16-bit comparison lands; use u8 for that.

CONST ADDR

poke() needs a constant address

No computed addresses yet

poke(screen(12, 15), value) works and value can be any expression, but the address must be known at compile time, so screen() and color() take constant rows and columns. A computed address is a compile error.

NO RECURSION

Functions cannot call themselves

No stack frame

Parameters and locals live at fixed zero-page addresses, so a function that calls itself, directly or through another function, is a compile error. &&, ||, *, / and shifts on variables are compile errors too, and the right-hand side of + - & | ^ and of comparisons must be a literal, a variable or a hardware register.

Contributions welcome. The compiler is <1,500 lines of TypeScript with a comprehensive test suite. If you want to add arrays, multiplication, or more hardware registers, the source is on GitHub.
