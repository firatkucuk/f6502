Nyan Cat

A terminal-inspired C64 take on Nyan Cat: a navy sky, a pink pixel cat, a six-band rainbow trail, scattered stars, and the familiar terminal caption. The scene runs as 6502 machine code in the f6502 emulator.

// ── Sprite data: Nyan Cat silhouette, 24 × 21 px, single colour ──────────────
//    Placed at $0A00 (sprite pointer value = $0A00 / 64 = 40 = 0x28)
//    Screen-pointer register is at $07F8 (screen base $0400 + $3F8).
data @addr(0x0A00) {
  cat: [u8; 63] = [
    0x0C, 0x60, 0x00,   // row  0: . . . . # # . . . # # . . . . . . . . . . . . .
    0x0C, 0x60, 0x00,   // row  1: (ears)
    0x1F, 0xFC, 0x00,   // row  2: . . . # # # # # # # # # # # . . . . . . . . . .
    0x3F, 0xFE, 0x00,   // row  3: . . # # # # # # # # # # # # # . . . . . . . . .
    0x7F, 0xFF, 0x00,   // row  4: . # # # # # # # # # # # # # # # . . . . . . . .
    0x67, 0x9F, 0x00,   // row  5: . # # . . # # # # . . # # # # # . (eyes)
    0x7F, 0xFF, 0x00,   // row  6
    0x7F, 0xFF, 0x00,   // row  7
    0x7F, 0xFF, 0x00,   // row  8
    0x3F, 0xFE, 0x00,   // row  9
    0x3F, 0xFE, 0x00,   // row 10
    0x33, 0x32, 0x00,   // row 11: . . # # . . # # . . # # . . # . (legs)
    0x33, 0x32, 0x00,   // row 12
    0x33, 0x32, 0x00,   // row 13
    0x30, 0x02, 0x00,   // row 14: . . # # . . . . . . . . . . # . (paws)
    0x00, 0x00, 0x00,   // rows 15-20 (blank padding)
    0x00, 0x00, 0x00,
    0x00, 0x00, 0x00,

// ── ZP variables ──────────────────────────────────────────────────────────────
let @zp catX:    u8 = 220;   // sprite X (left-edge in low-8-bit range)
let @zp rainbow: u8 = 0;     // current border colour index (0-15)
let @zp frame:   u8 = 0;     // frame counter (wraps; drives rainbow speed)
let @zp outer:   u8 = 0;     // delay outer counter
let @zp inner:   u8 = 0;     // delay inner counter

// ── Delay function (~0.4 s at 1 MHz) ─────────────────────────────────────────
@inline fn delay(): void {
  outer = 0;
  loop {
    inner = 0;
    loop {
      inner = inner + 1;
      if (inner == 0) { break; }
    }
    outer = outer + 1;
    if (outer == 64) { break; }
  }
}

How it works

VIC-II sprites

24 × 21 px hardware sprites, 63 bytes each

The C64's VIC-II chip supports eight hardware sprites. Each is 24 pixels wide and 21 pixels tall — three bytes per row, MSB on the left. Sprite data must sit on a 64-byte-aligned address; you tell the VIC-II where by writing address / 64 to the sprite-pointer register at $07F8. The Nyan Cat sprite is placed at $0D00, so the pointer value is 52.

The data @addr(0x0A00) { … } block in C64Script declares the sprite bytes at an absolute address. The compiler pads the binary with zeros up to that address before emitting the data.

sprite data — rows 0–5 shown 
data @addr(0x0A00) {
  cat: [u8; 63] = [
    0x0C, 0x60, 0x00,  // row 0: . . . . # # . . . # # . (ears)
    0x0C, 0x60, 0x00,  // row 1
    0x1F, 0xFC, 0x00,  // row 2: . . . # # # # # # # # # (head)
    0x3F, 0xFE, 0x00,  // row 3
    0x7F, 0xFF, 0x00,  // row 4: . # # # # # # # # # # # (full width)
    0x67, 0x9F, 0x00,  // row 5: . # # . . # # # . . # # (eyes hollow)
    // ... 15 more rows
  ];
}

Screen codes & poke()

Writing the splash text to character RAM

The C64's character screen is a 40×25 grid of bytes at $0400. Each byte is a screen code — not ASCII: A–Z map to 1–26, digits 0–9 to $30–$39. Colour RAM at $D800 mirrors the layout; one nibble per character sets its foreground colour (0–15).

C64Script's poke(addr, val) built-in emits a LDA #val / STA addr pair. The compiler picks zero-page or absolute addressing automatically.

"F6502" on row 10 — addr = $0400 + 10×40 + 17 = $05A1 
poke(0x05A1, 0x06);  // 'F' screen code 6
poke(0x05A2, 0x36);  // '6' = 0x30 + 6
poke(0x05A3, 0x35);  // '5'
poke(0x05A4, 0x30);  // '0'
poke(0x05A5, 0x32);  // '2'
// colour RAM — LIGHT_BLUE = 14
poke(0xD9A1, 14);  poke(0xD9A2, 14);  // … × 5

Raster-synced animation

~50 fps without timers, using VIC-II line 200

The VIC-II draws the screen one scan line at a time, top to bottom. VIC2.rasterLine ($D012) returns the line currently being drawn. Waiting for line 200 — safely below the sprite — then waiting past it ensures exactly one frame of execution time per iteration (~50 Hz PAL), giving smooth, tear-free motion with no hardware timers.

animation loop 
loop {
  while (VIC2.rasterLine != 200) {}  // wait FOR line 200
  while (VIC2.rasterLine == 200) {}  // wait PAST line 200

  VIC2.sprite0x = catX;  // update position
  catX = catX - 2;       // wraps 0 → 254 naturally

  frame = frame + 1;
  if (frame == 2) {
    frame = 0;
    VIC2.borderColor = rainbow;
    rainbow = rainbow + 1;
    if (rainbow == 16) { rainbow = 0; }  // cycle 0–15
  }
}

@zp variables & @inline

Faster, smaller 6502 code with two annotations

The 6502's zero page ($00–$FF) is special: instructions addressing it take two bytes instead of three and one fewer clock cycle. The @zp annotation places a variable there — a win inside tight animation loops like the raster wait.

@inline on delay() copies the function body at every call site instead of emitting JSR/RTS, saving the 12-cycle call overhead when the function is called repeatedly from the splash screen.

zero-page variables and inline delay 
let @zp catX:    u8 = 220;  // sprite X position
let @zp rainbow: u8 = 0;   // border colour index (0–15)
let @zp frame:   u8 = 0;   // frame counter

@inline fn delay(): void {
  outer = 0;
  loop {
    inner = 0;
    loop { inner = inner + 1; if (inner == 0) { break; } }
    outer = outer + 1;
    if (outer == 64) { break; }
  }
}

// Five inlined calls ≈ 2 s at 1 MHz
delay(); delay(); delay(); delay(); delay();
