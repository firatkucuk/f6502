# f6502 sub-project 1: cycle-accurate 6502 core and test harness

Date: 2026-10-10
Status: draft, awaiting review

## 1. Project context

f6502 is a browser-based 6502 / Commodore 64 emulator written in TypeScript. It is a library with no backend: a page includes the JS, attaches it to a canvas, and the emulation runs. The library fetches a binary from a URL and executes it.

Target scope is a full C64 (cycle-exact VIC-II, SID, disk and tape media). That is too large for one spec, so the project is decomposed. Each sub-project gets its own spec, plan and implementation cycle.

| # | Sub-project | Done when |
|---|---|---|
| 1 | **6502 core + test harness** (this spec) | Passes Klaus Dormann and per-cycle conformance suites in Node |
| 2 | C64 machine skeleton: PLA banking, ROM loading, CIA1/2, basic VIC-II text mode, browser layer, `.prg` loading | BASIC `READY.` prompt on canvas; typing works; a `.prg` runs |
| 3 | VIC-II complete: bitmap, multicolour, sprites, collisions, raster IRQ, scrolling | Typical games and demos render correctly |
| 4 | Cycle-exact VIC-II: badlines, BA/AEC stalls, sprite DMA, per-cycle pipeline | Raster-effect demos and VIC-II test suites pass |
| 5 | SID: voices, filters, AudioWorklet output | Music plays correctly |
| 6 | Media: `.d64`, `.t64`/`.tap` (1541 emulation vs KERNAL trap decided here) | Disk games load |
| Final | GitHub Actions CI and GitHub Pages site (how-to + live demo), started only after the preceding work is verified | Site deployed, CI green |

### Layering (project-wide)

```
browser/   Canvas renderer, keyboard -> C64 matrix, WebAudio, fetch loader, rAF loop
machine/   C64: memory map + banking, VIC-II, CIA1/2, SID, ROM loading, PRG/D64 loading
core/      MOS6502: registers, opcodes, addressing modes, cycle accuracy, IRQ/NMI
           Bus interface: read(addr) / write(addr, value)
```

`core/` never imports from `machine/` or `browser/`. The 6510 on-chip I/O port at `$00/$01` is machine-layer, memory-mapped behaviour.

### Project decisions already made

- Packaging: ESM build plus a minified IIFE browser bundle exposing a global `F6502`.
- Licence: Apache-2.0.
- Test ROMs and ROM images are not vendored. Klaus Dormann test binaries are GPL; C64 KERNAL/BASIC/character ROMs are copyrighted.
- The eventual demo uses OpenROMs by default, with user-supplied original ROMs as an option. OpenROMs licence compatibility with the Pages site is to be confirmed at that time.

## 3. Architecture

### 3.1 Module layout

```
src/core/
  bus.ts        Bus interface
  cpu.ts        MOS6502 class: registers, step(), reset(), IRQ/NMI lines
  flags.ts      status-flag constants
  opcodes.ts    256-entry metadata table (mnemonic, mode, official/illegal)
  index.ts      public exports
test/core/      Vitest tests
scripts/        fetch-test-data
```

### 3.2 Public API

```ts
interface Bus {
  read(addr: number): number;               // one call = one CPU cycle
  write(addr: number, value: number): void; // one call = one CPU cycle
}

interface CpuHooks {
  // Called once per cycle, after the bus access completes.
  onCycle?(): void;
}

class MOS6502 {
  constructor(bus: Bus, hooks?: CpuHooks);
  reset(): void;                  // loads PC from $FFFC, 7 cycles
  step(): number;                 // runs one instruction, returns cycles consumed
  setIrq(level: boolean): void;   // level-sensitive
  setNmi(level: boolean): void;   // edge-detected internally
  readonly regs: { a: number; x: number; y: number; sp: number; pc: number; p: number };
  cycles: number;                 // running cycle counter
  halted: boolean;                // set by JAM opcodes, cleared by reset()
}
```

### 3.3 Clock model (approach B)

`step()` executes one whole instruction as ordinary code. Every bus access is exactly one cycle, including dummy reads and the RMW double write, and triggers `onCycle`. The machine ticks the other chips from that hook.

BA stalls need no CPU logic: the machine's `Bus.read` blocks (ticking other chips) while BA is low, matching the 6510, which stalls only on read cycles.

Rejected alternatives:
- Micro-op state machine: more code, slower in JS, more room for subtle bugs.
- Instruction-level execution with a cycle-count table: cannot support cycle-exact VIC-II (sub-project 4) without a rewrite.

Known limit: execution cannot be paused mid-instruction; debugger stepping is per instruction.

### 3.4 Instruction structure

Three parts:

1. **Addressing-mode helpers** compute the effective address and perform the exact bus accesses: `imm, zp, zpx, zpy, abs, abx, aby, izx, izy`, plus `rel`, `jmp (ind)`, implied/accumulator.
2. **Access kind** determines timing:
   - Read: indexed modes do the extra dummy read only on a page cross.
   - Write: the dummy read always happens.
   - Read-modify-write: read, dummy write of the original value, write of the new value.
3. **Operation functions** are pure register and flag logic with no bus access.

`step()` fetches the opcode and dispatches through one 256-case `switch`, each case composing a mode helper with an operation. A table-of-closures variant will be benchmarked during implementation; the faster one is kept. `opcodes.ts` metadata is off the hot path (disassembly, test generation).

### 3.5 NMOS quirks included from the start

- `JMP ($xxFF)` page-wrap bug.
- Branches: +1 cycle if taken, +1 more on a page cross.
- `BRK` pushes `B=1`; hardware interrupts push `B=0`; bit 5 always reads as 1.
- Working BCD (`D` flag) with NMOS flag behaviour.
- Stack and zero-page wrapping.

### 3.6 Interrupts

- IRQ is level-sensitive. NMI is edge-detected (line going low to high).
- Both are polled on the instruction's penultimate cycle.
- `I` flag changes from `CLI`/`SEI`/`PLP` take effect one instruction late. `RTI` takes effect immediately.
- A taken branch with no page cross has no poll at the end of its second cycle: an interrupt already pending at the end of its first cycle is serviced right after the branch, while one that first appears later waits one more instruction (a branch-to-self never starves interrupts).
- Interrupt sequence is 7 cycles. An NMI arriving during the first cycles of an IRQ/BRK sequence hijacks the vector: the `B` value pushed is unchanged and the NMI vector is fetched.

### 3.7 Illegal opcodes: all 256 defined

- Exact (stable): `SLO RLA SRE RRA SAX LAX DCP ISC ANC ALR ARR SBX`, extra `SBC $EB`, undocumented `NOP` variants (operand reads and page-cross cost), `LAS`.
- Unstable but deterministic in practice: `SHA SHX SHY TAS` use the "AND with high address + 1" behaviour, including address corruption on page cross.
- Analogue-dependent: `ANE`, `LXA` use a configurable magic constant, default `$EE`.
- JAM: the 12 JAM opcodes halt the CPU. `step()` returns and sets `halted`; only `reset()` clears it. No exceptions are thrown.

## 4. Testing

| Tier | What | When |
|---|---|---|
| Unit | Hand-written quirk tests: JMP page wrap, BCD flags, IRQ/CLI delay, NMI hijack, branch polling, RMW double-write, JAM halt | Every local run |
| Conformance: Klaus Dormann | Functional, decimal, interrupt test ROMs run to known success addresses. The interrupt test uses a harness emulating its feedback register at `$BFFC` | `npm run test:conformance` |
| Conformance: SingleStepTests/65x02 | Per-cycle bus traces and final registers for all 256 opcodes | Sampled subset per opcode by default; full run on demand |
| Benchmark | Cycles per second in Node, as a regression guard | `npm run bench`, reported, not a gate |

`scripts/fetch-test-data` downloads the test ROMs and JSON from pinned commit SHAs with checksums into a git-ignored `.testdata/` folder. The suite sizes and licences of SingleStepTests/65x02 are to be confirmed during planning, and the fetch script's sampling strategy follows from that.

## 5. Tooling

- TypeScript strict, ESM source, Node LTS. No runtime dependencies.
- `tsup` outputs `dist/index.js` (ESM), `dist/f6502.min.js` (IIFE, global `F6502`), and `.d.ts`.
- Vitest, ESLint with a `core`-may-not-import-`machine`/`browser` boundary rule, Prettier.
- npm scripts: `build`, `test`, `test:conformance`, `lint`, `typecheck`, `fetch-test-data`, `bench`.
- `tsconfig` for `core/` excludes DOM libs.

## 6. Definition of done

1. Klaus Dormann functional, decimal and interrupt tests pass.
2. SingleStepTests cycle traces pass for all 256 opcodes, official and illegal, apart from documented analogue-dependent cases (`ANE`/`LXA` with the configured constant).
3. `npm run build` produces the ESM and IIFE bundles and type declarations.
4. `npm run lint` and `npm run typecheck` are clean, including the boundary rule.
5. All of the above verified locally and reported with command output.

GitHub Actions CI and the GitHub Pages site are explicitly not part of this definition of done; they follow as the final phase once everything is verified.
